# po-workbench 项目简介

## 一句话

本地运行的「邮政企业采购订单采集工作台」：用登录 Cookie 只读采集订单，把导出、列表、详情三个通道的字段合并成一份最全的订单库，并提供搜索与详情查看。

## 现在能做什么（v0.2.0）

- **工作台概览**（`/dashboard`）：订单总数、今日新增、商品明细、详情补全进度、最近入库订单，全部是数据库里的真实数据。
- **数据源设置**（`/settings`）：粘贴 Cookie → 加密保存 → 检验登录态。Cookie 用 AES-256-GCM 加密，前端不回显。
- **采购订单采集**（`/collection`）：
  - 按月导出全量（字段最全，主干数据，支持断点续跑）
  - 列表全量扫描（补订单备注、物流、商城价、审核状态）
  - 详情全量补全（补购货人、审核人链、操作日志等，可暂停）
  - 手动增量更新（默认近 7 天）
- **订单库**（`/orders`）：按订单号、收货人、机构、商品名称搜索，支持状态和日期过滤；详情页展示所有字段、商品明细、审核链和操作日志。
- **安全边界**：只读采集，不修改目标系统任何数据；不保存原始 HTML；服务只监听本机。

## 技术栈（一句话）

前端 React 19 + TypeScript + Ant Design 6 + Vite 6；本地服务 Node 22 + Express + SQLite（better-sqlite3）；HTML 用 cheerio 解析。`npm run dev` 同时启动 API（8787）和前端（5173）。

## 还没做 / 可以继续做的

1. 定时增量（当前坚持用户手动触发）
2. 采集失败订单的重试队列与可视化
3. 订单数据导出 Excel / CSV（从本地订单库导出）
4. Mac / Windows 数据同步（当前明确不做）
5. 更多采集平台（当前只接邮政内部采购系统）

## 环境要求

Node.js `20.19+` 或 `22.12+`。用 nvm 的话可执行 `nvm use 22`（项目自带 `.nvmrc`）。Node 18 跑测试会报错。
